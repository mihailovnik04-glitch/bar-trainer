# Барное пособие: PDF-раскладка и тренажёр граммовок

Два продукта из одного источника — Excel-файла с технологическими картами бара:

1. **`build/manual_final.pdf`** — свёрстанное пособие на 72 страницы A4: карточка на каждый напиток
   (фото, состав, украшения, способ приготовления, подача) плюс глава «Система» с закономерностями
   и мнемотехниками.
2. **`build/app/`** — веб-тренажёр на 567 вопросов по граммовкам, украшениям и посуде.
   Работает офлайн, режимы «экзамен» и «тренировка», раздел с ошибками, встроенный **справочник**
   (87 карточек коктейлей целиком + шпаргалки по системе) и всплывающая карточка рецепта
   по кнопке из фидбека и из списка ошибок.

## Железное правило проекта

**Данные из исходника переносятся дословно.** Ни одна граммовка, ни одно название ингредиента,
ни одна строка способа приготовления не переписываются «покрасивее» и не сокращаются.
Пересказывать можно только в главе «Система» — там это авторский текст, а не рецептура.
Скрипт `99_verify.py` проверяет дословность автоматически; он должен проходить перед каждой выдачей файлов.

Если в исходнике встречается очевидная ошибка (например, у «Бабл-ти лимонад · с собой» сумма
жидкостей 150 мл при заявленном выходе 190 мл) — **значение оставляем как есть** и сообщаем
об этом пользователю текстом, а не правкой данных.

## Установка

```bash
pip install openpyxl pillow playwright pypdf reportlab
python3 -m playwright install chromium
```

Шрифты (Inter, Manrope, JetBrains Mono, Playfair Display, кириллические сабсеты woff2) лежат в
`fonts/` и вшиваются в HTML в base64 — интернет при сборке не нужен.
Если понадобятся другие начертания: `npm pack @fontsource/<имя>` и распаковать в `fonts/`.

## Сборка

```bash
./build.sh            # обычная пересборка из готовых data/*.json (~40 секунд)
./build.sh --full     # + заново распарсить data/source.xlsx (нужен исходник)
```

Исходного `.xlsx` в репозитории нет — положите его в `data/source.xlsx`, если нужен `--full`.
Всё остальное (разобранные ячейки, якоря картинок, сами картинки) уже лежит в `data/` и `img/`.

## Как устроен исходник (и почему парсер такой)

Excel состоит из 13 листов. Листы с напитками (`Лонг Дринки`, `Шотики`, `Лимонады и БА`,
`Лимонады с собой (Акция)`, `Горячие`, `Самовывоз`) устроены одинаково, но **без объединённых ячеек** —
структура держится только на расположении:

| Колонка | Содержимое |
|---|---|
| A | название напитка — только в первой строке блока (в следующих строках A пустая) |
| B | ингредиент |
| C | граммовка; в последней строке блока — **выход** напитка |
| D | способ приготовления (одна или несколько строк); в строке с выходом — правило подачи |

Отсюда логика `01_parse.py`: новый блок начинается там, где A непустая, а в предыдущей строке A пустая.
Если A непустая две строки подряд — это перенос названия («Малиновый Взвар» + «с ежевикой»,
«Маракуйя-Мандарин» + «Кувшин» + «Безо льда»), части склеиваются через ` / `.

Фотографии привязываются по строке якоря из `images.json`: фото принадлежит блоку, если его
`row` попадает в диапазон строк блока. Колонка > 2 означает дополнительное фото
(альтернативное украшение) — оно кладётся в `extra_photos` и в вёрстке сейчас не используется.

## Формат `drinks2.json`

```jsonc
{
  "sheet": "Лонг Дринки",
  "name": "Сицилийский джин-тоник",
  "total": "180 мл",
  "serve": "Коктейль подается с трубочкой с изгибом",
  "method": "Охлажденный бокал \"Банка\"…",   // дословно, \n между абзацами
  "ing":      [["Джин Босфорд", "40 мл"], …], // всё подряд, как в файле
  "ing_main": [["Джин Босфорд", "40 мл"], …], // без украшений
  "garnish":  [["ПФ Пастила Лимон укр", "1 шт - 2 гр"], …], // где в названии есть «укр»
  "glass": "Банка",          // вычислено регуляркой по method + ручные правки в GLASS_FIX
  "tech": "Билд",            // Билд | Шейк | Стир | Блендер | Питчер
  "straw": "Трубочка с изгибом",
  "formula": [["40", "джин босфорд"], …],     // для строки-формулы в карточке
  "photos": ["media/image41.png"],
  "extra_photos": []
}
```

Разделение на украшения — по подстроке `укр` в названии ингредиента. Это единственный признак
в исходнике, других нет.

### Ловушки распознавания, уже обойдённые

* `tech`: бокал в меню называется **«Шейкер»**, поэтому нельзя искать слово «шейкер» — только
  «шейкерный стакан» / «взбить». Иначе Турбобой, Бомбалейло и Токийский Дрифт станут «шейками», хотя они билды.
* `Бамбл` и `Криспи Айс Латте` упоминают питчер (в нём варят кофе), но это билды — правится через `TECH_FIX`.
* `Рафунтелла` — «взбить» на пароотводе, а не шейкер: тоже `TECH_FIX`.
* Посуда пишется в исходнике по-разному: «Олд фешн» / «Олд Фешн», «Банка с ручкой» с латинской `c`.
  Нормализация — `GLASS_NORM` в `40_bank.py`.
* Варианты «Безо льда» не имеют своего состава (ссылаются на базовый рецепт) — в вёрстке они
  идут компактным блоком `variant_block()` сразу за родительской карточкой, а из тренажёра исключены.

## Что уже проверено на данных (не пересчитывать заново)

* **Выход = сумма всех жидкостей.** Сходится у 84 напитков из 87 с указанным выходом.
  Исключения: `Глинтвейн Алко` (140 → 130, уваривается), `В Питере — пить!` (запись «6*50 мл / 300 мл»),
  `Бабл-ти Лимонад · с собой` (сумма 150 при заявленных 190 — ошибка исходника, оставлена как есть).
* **Цитрусовая лестница украшений:** вейджи убывают по 5 г (апельсин 30 → лимон 25 → лайм 20 → яблоко 15),
  кольцо = вейдж − 5, полкольца = половина кольца.
* **Кувшин лимонада = бокал ×3.** Лимонделло даёт 540 мл, потому что его база 180, а не 200 — правило не нарушено.
* **Суперджус Лимон** встречается в 42 блоках; дозы 10 / 20 / 30 мл (14 / 10 / 10 раз).
  10 мл — в билдах с тоником и содовой, 20–30 — в шейках, блендере и шотах.
* Техники по 98 блокам: Билд 68, Шейк 13, Питчер 12, Блендер 3, Стир 2.

## Вёрстка PDF: грабли Chromium

Печать идёт через `page.pdf()` без полей, поля заданы в CSS. Три вещи, которые ломают вёрстку молча:

1. **Любой элемент шире страницы включает shrink-to-fit** и ужимает весь документ (мы ловили масштаб 0.8
   из-за одной картинки в натуральную величину). Спасает глобальное `img{max-width:100%}` в `style.css` — не удалять.
2. **Отрицательные margin не дают вылезти за margin box**, если PDF печатается с полями. Поэтому
   `@page{margin:0}`, поля — это `padding` у `.sheet`, а обложка получает полноформатную заливку.
3. **Номера страниц через `footerTemplate` требуют полей**, которых у нас нет, поэтому их
   штампует `31_stamp.py` поверх готового PDF шрифтом DejaVu (в built-in шрифтах reportlab нет кириллицы).

Одна и та же `build/index.html` — это и PDF, и экранная версия пособия: `@media screen` даёт липкую
навигацию и поиск, `@media print` их прячет.

## Правки вёрстки пособия

* **Порядок глав, состав главы, цвет главы** — `scripts/config.py`, список `CHAPTERS`.
  Название напитка в `items` должно совпадать с ключом в `drinks2.json` **посимвольно**,
  иначе `assemble.py` падает с «НЕТ НАПИТКА» (это специально).
* **Мнемоники под карточкой** — словарь `MNEMO` там же, ключ — то же имя напитка.
* **Текст главы «Система»** — `pages.py`, обычный HTML внутри f-строк.
* **Справочные главы** — `pages2.py`. Там данные тянутся из `data.json` по номерам строк и колонок,
  поэтому при смене исходника эти номера нужно перепроверять (`sheet_rows()` + `c(row, col)`).
* **Стили** — `style.css`. Карточка напитка: `.card`, состав `.ing`, формула `.formula`, мнемоника `.key`.

## Тренажёр

`quiz_template.html` — самодостаточный файл: стили, разметка и логика внутри, данные подставляются
вместо `__BANK__`. Правки интерфейса делать **в шаблоне**, потом `python3 scripts/41_app.py`.
Не править `build/app/index.html` напрямую — его перезатрёт.

### Справочник внутри приложения

`40_bank.py` собирает `data/recipes.json` из тех же `drinks2.json` + `config.py`, поэтому карточка
в приложении и карточка в PDF всегда совпадают — отдельного источника нет.

```jsonc
{"chapters":[{"id":"sprits","title":"Аперитивы и спритцы","color":"#B33A5B","sub":"…"}],
 "recipes":[{"name":"Аперол Спритц","ch":"sprits","tech":"Билд","glass":"Винный бокал",
             "straw":"Трубочка с изгибом","total":"200 мл",
             "ing":[["Аперитив Аперол","60 мл"],…], "gar":[["Апельсин","25 гр"]],
             "method":"…", "serve":"…", "formula":"60 аперитив аперол + …",
             "key":"мнемоника из MNEMO", "img":"image26",
             "var":[{"name":"… · Безо льда","method":"…"}]}]}
```

Экран «Справочник»: поиск по названию, ингредиенту, украшению и посуде; группировка по главам
(цвет берётся из `CHAPTERS`); тап по строке открывает модалку. Над списком — блок `CHEATS`
(сжатая глава «Система»: правило выхода, техники, трубочки, лестница украшений, лимонадная формула,
шкала доз, шоты, взвары, кофе, чай). `CHEATS` — обычная строка-константа в `quiz_template.html`,
данные в ней **зашиты руками**: при изменении рецептур проверять вручную.

### Картинки хранятся один раз

Раньше data-URI подставлялся в каждый вопрос, одна картинка дублировалась до 8 раз и `bank.js` весил 3,8 МБ.
Теперь вопрос и рецепт хранят **ключ** (`"image41"`), а сами изображения лежат в `window.IMG` (`media.js`),
460 px, JPEG q70. Итог: `bank.js` 87 КБ, `recipes.js` 81 КБ, `media.js` 1,3 МБ, одиночный `quiz.html` 1,5 МБ.
Функция `src(key)` в шаблоне разворачивает ключ в data-URI — новые места вывода картинок писать через неё.

### Модалка с рецептом

`openRecipe(i)` рисует карточку из `REC.recipes[i]` и показывает нижний лист. Вызывается из трёх мест:
кнопка «Открыть рецепт целиком» в фидбеке после неверного ответа, строка справочника, строка в списке ошибок —
все три несут `data-r` с индексом рецепта, обработчик один, делегированный на `document`.

Важная деталь: пока модалка открыта, вопрос **не должен листаться**. `openRecipe()` гасит таймер
автоперехода, а `onAdvance()` игнорирует тап, если он пришёлся на `#modal` или `#showRec`,
и переподписывается заново. Если будете трогать логику перехода — проверьте этот сценарий:
ошибиться → открыть рецепт → подождать 3 секунды → закрыть → тап должен листать.

### Формат вопроса

```jsonc
{"t":"num",    "cat":"grams",   "drink":"Сила земли", "q":"Сколько «Тоник ПЭТ 1л»?",
 "unit":"мл",  "a":100, "img":"image43", "r":8, "hint":"указано как «5 шт - 30 гр»"}
{"t":"choice", "cat":"garnish", "drink":"Улица Роз", "q":"Чем украшается напиток?",
 "opts":["…","…","…","…"], "ai":2, "img":"…"}
{"t":"glass",  "cat":"glass",   "drink":"Кабуки", "q":"В какой посуде подаётся напиток?",
 "opts":[…], "ai":1}
```

`cat` — тема (`grams` | `garnish` | `glass`), `t` — способ ответа (`num` — ввод числа,
`choice`/`glass` — выбор), `img` — ключ в `window.IMG`, `r` — индекс карточки в `window.RECIPES.recipes`
(его нет у вопросов про эталонные веса украшений — там показывать нечего). Экзамен набирает 75 вопросов квотами: 48 + 7 по составу,
12 + 5 по украшениям, 3 по посуде (`pickExam()` в шаблоне).

### Требования заказчика к вопросам — соблюдать

* Спрашивать **только** граммовки компонентов, украшения (включая их вес) и посуду.
  Вопросы про выход напитка, технику, трубочку и порядок действий — не добавлять.
* Ввод точного значения — основной формат (сейчас 84% банка). Вопросы с вариантами — меньшинство.
* В вопросах с вариантами неверные значения отстоят от верного **минимум на 10** и максимум на 40
  (`steps_for()` в `40_bank.py`); `99_verify.py` это проверяет.
* Посуды — по минимуму (34 вопроса), и только характерная тара: список `GLASS_RARE`.
  Банка и винный бокал намеренно исключены — они слишком частые, вопрос вырождается.
* Названия ингредиентов — ровно те же, что в пособии, без сокращений.
* Дистракторы для украшений и посуды берутся из **реальных** наборов других напитков, не выдумываются.

### Прогресс и хранение

`localStorage` под ключом `barquiz.v1`: `{errors:{индекс_вопроса: сколько_раз}, stats:{runs,best,right,total}}`.
Индекс вопроса — позиция в массиве `BANK`, поэтому **при пересборке банка старые ошибки могут «съехать»**
на другие вопросы. Если менять генерацию вопросов — поднять ключ до `barquiz.v2`,
либо перейти на стабильные id (например, хеш от `drink + q`).

### Известные мелочи UI

* После неверного ответа переход дальше по тапу в любом месте или Enter; слушатель висит на `document`,
  а не на карточке — клик по `disabled` полю ввода событий не даёт.
* Клавиши 1–4 выбирают вариант, Enter отправляет число.
* Тёмная тема жёстко зашита, светлой нет.
* Модалка закрывается тапом по фону, крестика нет — только «шторка» сверху и Esc на клавиатуре.
* Фото в модалке выводится через `object-fit:contain` — коктейли сняты вертикально, `cover` резал бокал.
* PWA нет: ни манифеста, ни service worker. Для «добавить на экран» нужен хостинг (Netlify Drop / GitHub Pages).

### Python на машине разработки

На текущей Windows-машине настоящего Python нет — `python.exe` в `WindowsApps` это заглушка
Microsoft Store. Пересборка (`build.sh`) без него невозможна. Ставить так:

```powershell
winget install --id Python.Python.3.12 -e
# перезапустить терминал, затем:
pip install -r requirements.txt
python -m playwright install chromium
```
